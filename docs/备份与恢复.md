若未来这些外部运行时被删除，仅恢复配置不能恢复RIFE运行环境。实施阶段要单独记录这些依赖版本/位置；不得用“配置可恢复”宣称完整环境可重建。

## 3. 验证和隔离恢复演练

仓库提供Python标准库工具 `tools/mpv_config_backup.py`（Python3.9+，本机测试版本3.9.1）：

```powershell
$backup = 'D:/workspace/小项目/mpv插件/_备份/缩放插件/mpv-config-20261002-233943'
python tools/mpv_config_backup.py verify --backup $backup --compare-source
python tools/mpv_config_backup.py rehearse --backup $backup
python -m unittest discover -s tests -v
```

- `verify`核对manifest/ZIP回执、payload逐文件哈希、ZIP成员与内容、目录结构和计数。
- `--compare-source`额外比较记录中的当前源路径，不会写入源。如果未来mpv配置有意修改，源比较失败是预期现象；去掉该开关仍可单独验证旧快照。
- `rehearse`仅在系统临时目录模拟恢复54个mpv配置文件，并确认模拟旧配置被保留；**不写活动mpv、不恢复D:/MPV启动器**。
- 实际检查结果与候选指纹记入 `docs/验证/`，不是把未来测试计划当作已完成测试。

完整性校验不是加密签名或恶意篡改认证；恢复前核对仓库中固定的manifest/ZIP指纹，妥善保存私有备份。

## 4. 将来真的需要恢复时

### 先预演，不覆盖

先关闭mpv，确认目标目录与备份确实对应，再运行默认dry-run：

```powershell
$backup = 'D:/workspace/小项目/mpv插件/_备份/缩放插件/mpv-config-20261002-233943'
$target = Join-Path $env:APPDATA 'mpv'
python tools/mpv_config_backup.py restore --backup $backup --target $target
```

此命令只验证并显示 `DRY_RUN`。**本轮没有执行下面的真实恢复命令。**

### 显式执行（仅在用户决定恢复时）

```powershell
# 确认上面的backup/target，关闭mpv后才执行
python tools/mpv_config_backup.py restore --backup $backup --target $target --apply --confirm RESTORE-MPV-CONFIG
```

工具先验证所有快照内容，在目标父目录建立临时新配置并再次验证，然后将现有mpv目录重命名为同级 `mpv.before-restore-<时间戳>`，再安装完整快照。成功后核对目录与哈希；保留原现场目录，不直接删除用户新增文件。

- 仅恢复 `mpv-config` 根（54文件），不会自动覆盖另存的启动器或外部运行时。
- 目标必须明确指定、目录名为mpv、父目录已存在；拒绝与本仓库/备份目录重叠以及链接/reparse路径，也拒绝含mpv.exe/mpv.com/portable_config的播放器安装目录（不是配置目录）。
- Windows活动APPDATA/mpv目标若检测到mpv.exe运行会拒绝恢复；检测失败亦不继续。其他目标不会检测播放器进程，结果JSON会明确给出 `NOT_CHECKED_NON_APPDATA` 和手动关闭播放器的警告；dry-run本身不证明播放器已关闭。
- 复制或目录安装失败会尝试恢复原目录；能成功改名时，验证失败的新目录保留为 `mpv.failed-restore-*` 供排查。如果保留失败目录或归位原目录也失败，工具同时报告原始错误、回滚错误、原现场及当前目标位置，绝不为强行归位覆盖二者。权限、断电或外部并发修改仍可能阻止回滚，遇到异常应停止，检查保留的现场，不继续反复覆盖。
- 这是普通文件目录恢复，不是跨进程事务/OS沙箱，不支持ACL的逐位还原。恢复期间不要启动mpv或让其他程序修改目标。

如确实需要恢复 `mpv-RIFE.cmd`，先另存当时的启动器，再人工核对 `payload/mpv-launcher/mpv-RIFE.cmd` 后覆盖；不要把54文件的自动配置恢复误认为55文件/完整运行时全部恢复。

## 5. 日后开发的回退分层

1. **菜单关/退出**：恢复本插件管理范围内的运行时状态；外部改链后让出控制，不覆盖陈旧快照。
2. **卸载插件**：移除本项目自己的文件/管理块，不清空用户其他shader与RIFE。
3. **配置灾难恢复**：必要时用本文完整快照与明确确认的恢复流程。
4. **代码回退**：Git回到已验收commit/tag；Git本身不恢复APPDATA配置或外部运行时。

每次部署前另做新的配置快照，不能因为已有本次备份就省略部署前备份。
