### LUA-1 非释放型 fallback（takeover 仍为 true）下旧链/回滚链继续生效，但 RGB/HDR 守卫、Integer 几何重算与链验证全部停摆，且可能谎报「已回退到 off」

### LUA-2 回滚重放失败时会把验证失败的链原样留下；回滚重放还跳过了 RGB/HDR 守卫

- 复核：🟡 部分成立；严重度 medium → **low**；类别 bug；工作量 S
- 位置：`scripts/scale-selector.lua:1365`，`scripts/scale-selector.lua:1376`，`scripts/scale-selector.lua:1605`，`scripts/scale-selector.lua:1627`，`scripts/scale-selector.lua:1648`，`scripts/scale-selector.lua:1691`
- 证据：rollback_after_verify_failure 调 activate_gear(stable_id,{from_rollback=true}) 后，只用 `if S.state == "active" or S.state == "fallback" then enter_fallback(S.active or stable_id, reason, false)`（:1376-1379）收尾，没检查重放是否真的成功。activate_gear 的多个提前返回路径都不会撤掉失败档的写入：integer 计划失败直接 return，S.state 仍为 active、S.active 仍是失败档（:1627-1634）；稳定档 shader 文件此间被删时 enter_fallback(...,first=false)（:1648-1658）；写入失败时回滚到的 prev_values 也是失败档的 last 值（:1664、:1691-1699）。这些情况下，失败档的链（缺 DESC、可能编译失败）会以 fallback 状态长期残留，与头部「无半生效/陈旧 pass」（:54）和 :1364 注释相悖。另外 from_rollback 会跳过激活侧守卫（:1605-1616），而 verify_chain_tick 只对当前失败档做过守卫复核（:1318），从未对 stable 档复核；stable 是 LUMA 档、当前源已变为 RGB/HDR 时，会被无守卫地重放。
- 建议：重放后判定 `S.state == "active" and S.active == stable_id`，不满足就 release_all_to_fallback(reason)，保证零残留。from_rollback 只用来跳过重复的 OSD 提示，不要跳过守卫：先用当前 vo 对 stable 档做 activation_guard_reason，被拒则直接整链释放。
- 复核意见：代码层面属实：rollback 调 activate_gear 后没有检查重放是否成功（:1376-1379）；Integer 计划失败的提前返回不改 S.state/S.active（:1627-1634），写入失败时 prev_values 取的是失败档的 S.last（:1664-1666），这些情况下失败档的写入会以 fallback 态留下；from_rollback 也确实跳过了激活侧守卫（:1605-1616）。但每条失败路径都很难触发：verify_chain_tick 在 vo==nil 时早已提前返回（:1311-1315），所以重放时 integer_k 为 nil 的可能性极小；stable 档的 shader 恰好在约 4.8s 窗口内被删也很少见；守卫被绕过要求「stable 为 LUMA 档，失败档为 RGB 可用档，且源恰好在验证窗口内切到 RGB」，因为源变化时 active 档的守卫释放会把 stable 置为 off（:1538-1539）。属于真实的防御缺口，但影响被高估，降为 low。「重放后判定成功，否则整链释放」的建议成本低且合理。

### LUA-6 Integer 的 video-zoom 用 math.log(k, 2)，在 PUC Lua 5.1 构建的 mpv 上会静默算成自然对数

- 复核：✅ 确认；严重度 low → **low**；类别 robustness；工作量 S
- 位置：`scripts/scale-selector.lua:1441`，`scripts/scale-selector.lua:2494`，`scripts/scale-selector.lua:2500`，`scripts/scale-selector.lua:1489`
- 证据：`g.set[#g.set + 1] = { prop = "video-zoom", op = "set", value = math.log(k, 2) }`（:1441）。第二参数 base 是 Lua 5.2 才加的；LuaJIT 作为 5.2 扩展支持它，但 PUC Lua 5.1 会忽略第二参数而返回 ln(k)。mpv 支持 lua5.1/lua5.2/luajit 三种构建（部分发行版或没有 LuaJIT 的架构用 lua5.1），这种构建下 k=2 时 zoom=0.693，实际放大约 1.62×，不是整数倍。读回校验（:1489）读到的正是这个错误值，所以能通过，不会报错。selftest :2494/:2500 用同一表达式加 `zoom == 1.0` 精确比较，只在该构建上运行 selftest 才会暴露。现有验证只在官方 Windows（LuaJIT）构建上跑过。

- 复核意见：核实 :1441 用的是 math.log(k, 2)。base 参数是 Lua 5.2 才有的；LuaJIT 作为扩展支持它，PUC Lua 5.1 会忽略它而返回 ln(k)，在那种构建上 zoom 会算错，读回校验（:1489）照样能通过。selftest :2494/:2500 用同一表达式加 zoom==1.0 精确比较，只有在该构建上跑 selftest 才会失败暴露。官方 Windows 构建用 LuaJIT，当前目标环境不受影响，所以是低严重度的可移植性问题，改成 math.log(k)/math.log(2) 的成本极低。

### LUA-7 读取审计 journal 满 512 后每次读都整表左移，且会让 GEO-01 selftest 变成恒真；验证 tick 每次重复取两遍 vo-passes
