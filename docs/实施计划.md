## 1. 全局约束（所有阶段适用）

1. **不改 mpv 内核**：只用 Lua 控制层 + 用户 shader（`glsl-shaders`）+ 内建缩放/显示属性（`scale`/`cscale`/`dscale`、`video-unscaled`/`video-zoom` 等）。
2. **一次只挂一条主缩放链**：FSR/NIS/SGSR 等候选不得追加在现有 Anime4K 链之后叠加运行；选择即替换。
3. **保留既有绑定**：CTRL+1…6（stock Anime4K）与 F7（RIFE）不动。F8 为菜单候选键，实施前必须审查 scripts 中已占用绑定，冲突则换键并在菜单标注。
4. **Off 语义**：只恢复插件接管时记录、且之后未被外部修改的托管属性。禁止 `glsl-shaders-clr` 全清；禁止用陈旧快照覆写外部改链；"关"不等于停止 mpv 必需的缩放与色彩管理。
5. **首版显式固定**：`gpu-next` 后端与选定 GPU API、SDR YUV 输入、以 1080p→1440p 为主场景。RGB/HDR 只做检测与回退/禁用，另行立项承诺。
6. **实际 pass 检测**：LUMA hook 在 RGB 输入可能不触发；每个档位必须检测真实 pass（`vo-passes`/hook 事实）与 WHEN 跳过，菜单显示真实生效状态与回退原因，禁止"菜单写 FSR、实际在用内建 scaler"。
7. **几何防反馈**：目标尺寸/几何只能基于 `video-out-params` 与窗口/OSD 实际像素（含旋转/SAR 换算），禁止读取已被上一级 shader 缩放过的视频尺寸造成反馈循环。
8. **来源与许可固化**：每个第三方 shader 记录 URL、抓取时间、SHA-256、许可证（沿用 `docs/证据/` 取证索引格式）。研究证据只证明可行性，**不直接当可发布 shader 包**；P5 前逐文件复核再分发条款。
9. **禁用项不冒名**：LS1 无原实现/权重/移植许可，BCAS 身份未核实——菜单禁用并显示原因；若做 CAS / Bicubic+CAS 必须独立命名，不得冒充截图项。
10. 全部验证遵守[测试计划](测试计划.md)的隔离、记录与测量规范。

## 2. 运行时状态模型（ownership / conflict / failure）

托管属性：`glsl-shaders` 列表、`scale`/`cscale`/`dscale`、插件设置的显示几何。

| 状态 | 进入条件 | 行为 |
|---|---|---|
| `off` | 未接管 | 首次接管时把当前值记为托管基线 |
| `active(档位)` | 用户选择某档 | 一次仅一档；显示实际生效 pass 与参数 |
| `external` | 检测到托管属性被外部修改（用户按 CTRL+1…6、其他脚本改链） | 插件停止覆盖并让出；菜单显示外部状态；Off 先 diff 提示，经用户确认后才恢复插件拥有且未冲突的部分 |
| `fallback(原因)` | 缺 shader、编译失败、格式不匹配、WHEN 跳过、RGB 下 LUMA 未触发等 | 显示真实状态与原因，回退到上一稳定状态；不得留下半生效链（部分 shader 残留） |

冲突规则：外部修改优先于插件快照，插件永不静默覆盖；恢复操作必须先对比托管快照与当前值。对应验证见[测试计划](测试计划.md) CTL 组。

## 3. 角色定义

- **实施者**：编写 Lua、shader 适配、工具与用户文档的角色。
- **验证者**：按[测试计划](测试计划.md)执行矩阵并记录证据的角色（可与实施者同人，但验收门槛须分别确认）。
- **用户**：配置所有者与唯一授权人；决定偏好、默认档与 P5 部署许可。
- **leader**：集成准备工具与文档，统一执行隔离检查并锁定候选；补证后共有 32 项单元测试（覆盖运行检测、二次回滚失败等），结果以 `docs/验证/准备检查-v2.json` 为准。独立复审只能对同一候选给出结论；后续修改须重做受影响检查。

- 环境事实：mpv `v0.40.0-393-gad59ff1b4`、libplacebo `v7.357.0`；`profile=high-quality` 已含 `scale=ewa_lanczossharp`。后续测试显式固定 VO/API，不依赖默认值推断。
- 负责人角色：leader（准备交付）、用户（配置所有者）。
- 验收门槛：备份 `verify --compare-source` 通过（配置未再变时）；32 项单测全过；`check_preparation.py` 通过；两路复审无阻断意见。

- 回退：P0 无运行时变更；若备份校验失败则重做快照，不得进入 P1。

### P1 插件骨架、状态管理与 Off（仅隔离临时配置）

- 依赖：P0。
- 范围与交付物：仅 `--config-dir` 临时配置运行，不写 APPDATA/mpv。Lua 菜单骨架（F8 候选键经脚本绑定审查后确定）；`off/active/external/fallback` 状态机；托管快照与恢复；"关"档位；外部改链检测与让出；退出清理；禁用项（LS1/BCAS）占位与原因文案。
- 负责人角色：实施者（编码）、验证者（CTL 组）、用户（交互与文案确认）。
- 验收门槛：CTL-01…CTL-08 通过；快速切换与退出后无 shader/几何残留；Off 不全清、不覆写外部改动。
- 退出条件：CTL 门槛全过 + 用户确认交互可接受。
- 回退：删除临时配置目录即可；活动配置不受影响；代码回退 Git 基线。

### P2 SDR 最小验证包

- 依赖：P1 状态机稳定。
- 范围与交付物：关 / stock Anime4K / FSR1 / SGSR1 / Nearest Neighbor；SDR YUV，先 1080p→1440p；显式固定 `gpu-next` 与 GPU API。
  - FSR1：固定版本+SHA-256 的 EASU+RCAS port 适配（`//!PARAM` 或版本化文件）；每轴≤2×、超出尺寸由 mpv 接管的行为验证。
  - SGSR1：固定版本 port；亮度适配（绿色通道依据改为亮度）差异记录在案；`gather`/PARAM/0–1 钳制核验。
  - Nearest：`scale=nearest` + 明确 cscale 策略（未设时本构建跟随 scale，须显式决策并记录）。
  - stock Anime4K：整链作为菜单选项引用，不修改内容、不重下另一套。
  - RGB 输入下 LUMA 档的检测与回退；8bit/10bit 双深度验证。
- 负责人角色：实施者、验证者（SHD/CTL 回归）、用户（初步偏好）。
- 验收门槛：SHD-01…SHD-04、SHD-08…SHD-11、SHD-13 通过；CTL 回归不破坏。其中 SHD-11 仅检查 HDR 的识别/禁用/回退，不是 HDR 画质验收；完整公平画质对照 PIC-01 统一留在 P4。
- 退出条件：门槛全过；用户确认最小包去留。
- 回退：菜单切回"关"；候选 shader 文件独立可删；打 P2 标签。

### P3 NIS compute 与像素风/整数档

- 依赖：P2（pass 检测与回退机制已稳定）。
- 范围与交付物：
  - NIS：NVScaler.glsl 固定版本+SHA-256；compute 编译、工作组、边界写入与系数纹理验证；确认已含锐化、**不再叠加 NVSharpen**。compute 非 gpu-next 专属，但首版只在固定后端验证以减少兼容面。
  - xBR：选定版本（记录来源与许可）移植为 MAIN hook 单/多 pass；`vf=xbr` 仅作预验证入口，其算法版本另记录，不与 GPU 版混称。
  - Sharp Bilinear：AUTO 变体（`floor(output_h/input_h+0.01)`，1080p→1440p 得 1 即退化为普通双线性）与手动 2× 预缩放分别命名，UI 展示退化事实，不冒充 LS 同款参数。
  - Integer：Lua 计算 `k=floor(min(可用宽/源宽,可用高/源高))` + `video-unscaled`/`video-zoom` + nearest；k<1 回退正常缩小而非裁切；1080p→1440p 仅 1×（左右各 320px、上下各 180px 黑边）须 UI 明示。
- 负责人角色：实施者、验证者（SHD-05…07、GEO 组）、用户。
- 验收门槛：SHD-05…SHD-07、GEO-01…GEO-07 通过；每档位实际 pass 检测通过。
- 退出条件：门槛全过 + 用户确认。
- 回退：单项档位可独立禁用/隐藏，不影响其余档位；打 P3 标签。

### P4 画质、性能与 RIFE 共存验证

- 依赖：P2 必需；P3 各项可在此阶段并行验证。
- 范围与交付物：公平 A/B（同输入 hash、同帧、同输出尺寸、同 RIFE 状态与色彩设置）：高质量传统缩放基线（ewa_lanczossharp）/ stock Anime4K / 各新档位；PER 测量按[测试计划](测试计划.md)第 3 节规范（`vo-passes` 纳秒→毫秒、fresh/redraw 区分、预热、掉帧、帧节奏、温度/时钟）；RIFE 开启共存余量实测。
- 分开承诺：HDR 与 RGB 画质不在本阶段验收，另行立项；LS1/BCAS 维持禁用；不训练新网络、不重写 RIFE。
- 负责人角色：验证者（PIC/PER）、实施者（修复）、用户（主观验收、默认档决定）。
- 验收门槛：PIC-01…PIC-04、PER-01…PER-04 通过；证据齐套（输入 hash、候选 commit/hash、后端、参数、限制）。
- 退出条件：验证报告汇总；用户决定默认档；无数据项如实标注"未测"。
- 回退：默认档维持用户原配置/stock Anime4K；活动配置保持零改动。

### P5 部署、卸载与文档（显式许可后）

- 依赖：P4 通过 + 用户明确同意。
- 范围与交付物：部署前新配置快照（不得复用旧快照）；可识别管理范围的安装/卸载（仅动本项目文件与管理块，保留用户其他 shader 与 RIFE）；用户文档（档位含义、状态/回退显示、卸载与恢复步骤、禁用项原因）；来源/许可清单终审。
- 负责人角色：实施者（工具与文档）、验证者（INS 组）、用户（唯一授权人）。
- 验收门槛：INS-01…INS-05 通过——先 dry-run 与隔离测试；真实写入须用户明确同意（`--confirm`）且已再备份；安装后功能抽检。
- 退出条件：用户接受安装结果，或选择回退。
- 回退：卸载工具；[备份与恢复](备份与恢复.md)的分层回退（菜单关→卸载→快照恢复→Git 回退）；卸载后恢复接管前状态。

## 6. 工期口径

原型（P1+P2）3–6 人日、八项选择器加 SDR 边界验证 1–3 周或更久，均为量级粗估，**不是承诺日期**；多后端、HDR 与完整画质评估另计。

## 7. 本轮明确不做

不开始 P1；不安装/启用任何档位；不改活动 mpv 配置与备份 payload；不实现 LS1 或冒名 BCAS；不训练网络；不重写 RIFE；不改 mpv 内核；不覆盖 leader 已交付的准备成果。
