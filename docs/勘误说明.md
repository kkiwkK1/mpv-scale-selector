# 初稿勘误与证据边界

前期流水线多次中止，`研究素材/` 中六份长篇初稿未完成统一交叉审查。保留它们仅为研究历史，不能因标有“实证”就视作最终验收。

**整合后的主结论以 [可行性研究报告](可行性研究报告.md) 为准。** 最终审查针对该报告的记录指纹及列明的证据，不是对全部早期初稿的逐条背书。

## 已明确纠正的根因

1. **算法身份错误。** SGSR 是 Qualcomm Snapdragon Game Super Resolution。截图研究针对空间 SGSR1，不是 AMD 算法，也不是 SGSR2 时域方案。FSR 指能从单帧视频接入的 FSR1，不扩展成 FSR2/3。
2. **检索范围错误。** 仅检索 agyild 的 repositories 不能推断其无相关实现；真正的 FSR、NIS、CAS、SGSR mpv 版本位于公开 Gists。其源码已下载到 `证据/port-*.glsl`，来源与指纹在取证索引中。先前“无任何移植”“不存在”式断言不再采用；零搜索结果也不能证明世界上不存在。
3. **整数倍缩放的错误数学旁注。** 整数放大时，并非所有输出像素都恰落在输入像素中心；Lanczos 等插值不自动等于 nearest。严格复制像素块必须选择 nearest，并验证对齐。正确的 1080p→1440p 最大无裁剪整数倍为1，720p→1440p可取2。
4. **接口混用。** RetroArch `#pragma parameter` 不等同 mpv 的 user-shader 参数机制。Sharp Bilinear 不应在 OUTPUT 直接取未经过后续颜色管理的 MAIN 替换最终图像；首选可变尺寸 MAIN 路线。修改 WIDTH/HEIGHT 只改变输出纹理，采样算法由 shader 自身负责。
5. **能力矩阵过度绝对化。** compute 不应写成只支持 gpu-next；vf=libplacebo 既支持 mpv shader 文件，就不能简单断言它绝无多 pass/compute。图形 API、封装支持、CPU/GPU 互通均须按实际路径核验。
6. **测量方法不成立。** 启动墙钟除以帧数、不同运行的总时间差、静态 pass 数量倍数不能替代 GPU 每帧算法耗时。初稿中的“释放9.7ms”“40倍”“0.1ms以下”“165Hz足够”等不作为最终性能证据。整合报告不提供未实测的绝对毫秒或FPS承诺。
7. **历史试验泛化。** 先前 ArtCNN/改造管线的失败不能推广为 stock Anime4K 和所有其他算法都无益。用户仍偏好 stock Anime4K；官方 Anime4K 也定位 native1080p动画。不能把“≤720p才值得用”设成未经用户验证的通用规则。
8. **把缺少配置行当成缺少生效配置。** 活动文件没有单独的 scale 行，但启用 `profile=high-quality`；本机构建查询证实其中包含 `scale=ewa_lanczossharp`。活动文件未显式设置VO，也不意味着当前一定不走gpu-next。
9. **原版同一性与授权。** LS1的公开实现/权重/授权没有取得；LSFG的专有声明不能移作LS1证明。BCAS定义未核实；CAS和Bicubic+CAS只能是另外命名的候选。FSR/NIS/SGSR亮度port不能承诺与Lossless Scaling RGB路径逐像素一致。

## 当前核实范围

- 接受：本机只读选项查询、固定mpv源码文档、实际下载的官方说明/许可、公开mpv port源码结构。
- 不接受为新测量：前期初稿的墙钟速度推导、未留存可复核日志的绝对性能比较、以仓库搜索零结果证明不存在。
- 尚需实现后确认：新port编译与运行、后端兼容、HDR/RGB、实际采样坐标、GPU余量、主观收益。

原始获取失败（如大小写不匹配的README或错误LICENSE路径）也留在索引中。另一个路径读取成功、文件正文含许可证时，最终结论引用成功内容，而不是把一次404误写成整个项目不存在。
