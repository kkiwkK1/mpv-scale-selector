# 验证证据留存策略（docs/验证/开发/）

- **性质**：这是一个**可撤销的默认决策**，不是不可变的协议；源于评审整改
  M-13/M-14（`docs/评审与修改意见-2026-10-11.md`）。策略变更须更新本文件并
  同步 `.gitignore`，不得只改其一。
- **适用范围**：`docs/验证/开发/` 下各 session（p1-001/p1-002/p2-001/p3-001/
  p4-001）的验证证据树。`docs/验证/` 顶层的准备期文件（准备*.json 等）不在此列。

## 1. 默认策略

1. **`*.log` 不入库**：`.gitignore` 的全局 `*.log` 规则继续生效，mpv 运行
   日志一律不提交。实测该目录现有 **1325** 个 `.log`
   （`find docs/验证/开发 -name "*.log" | wc -l`）。
2. **整目录不入库、留存本地磁盘、按 session 在仓库外归档**：`.gitignore`
   另有 `/docs/验证/开发/` 目录级忽略规则（注释指向本文件）。整目录实测
   约 **1.1 GB**（`du -sh`），远超仓库合理体积；且含超 GitHub 单文件 100MB
   硬限的日志（见第 2 节），整体入库不可行。
3. **机读清单与磁盘证据的一致性风险（如实记录）**：部分机读清单以纯路径
   引用这些日志，例如
   `docs/验证/开发/p1-001/objective-results.json`（实测 27 处 `.log` 引用）、
   `docs/验证/开发/p3-001/implementer/smoke-r2/evidence-manifest.json`
   （「路径 → SHA-256」映射）。本策略下仓库内将不存在这些日志文件——
   引用一律视为**指向磁盘/仓库外归档**，不是仓库内悬空引用的借口。归档时
   必须保持路径结构与哈希可核对（见第 3 节）。
4. **证据重产仍遵守 create-only**：不覆盖、不改写既有证据文件；本策略
   不改变该纪律。

## 2. 450MB 异常 verbose 日志：成因记录与处置建议（M-14）

- **对象**：`docs/验证/开发/p3-001/implementer/smoke-r2/SHD-11-a-hdr-override-guard.mpv.log`，
  实测 **471,062,010 字节**（`ls -l`，约 450MB）。
- **登记状态**：已以「路径 → SHA-256」登记于同目录 `evidence-manifest.json`
  （实测第 138 行，`3942d50ea940…5d860`）；`docs/验证/开发/p3-001/verify-lead/joint-drift-supplement.json`
  亦含同一哈希字符串。此前全项目**无任何处置记录**，本文件即处置记录。
- **成因记录（本会话实测）**：
  - 该日志是 SHD-11-a（HDR override guard）冒烟用例以 mpv **verbose（-v）**
    级别运行产生的会话日志；首行时间戳 `0.002s`，末行 `3111.430s`——回放
    文件播完后会话**空转约 51.9 分钟**才结束。
  - 空转期间每帧重复输出 `video EOF (status=3)`，实测该行重复
    **805,781 次**（`grep -c`）；verbose 下每行都写盘，体积随之膨胀到
    450MB 量级。
  - 即：成因是「verbose 采集 + 回放结束后会话长时间空转」的组合，属于
    采集方式问题，不代表用例本身需要这么大的证据。
- **处置建议**：
  1. **压缩后归档仓库外**（gzip/zstd 均可，该日志重复度极高，压缩比预期
     很好）。压缩归档不违反 create-only：原文件移出仓库目录而非原地改写。
  2. **移动前先记录、移动后更新处置说明**：`evidence-manifest.json` 等登记的
     路径/哈希在移动后将**指向已移走的文件**——本节即预先声明这一事实；
     实际移动时应在归档处（仓库外）保留「归档路径 + 原 SHA-256」对照表，
     避免证据链断裂。登记文件本身（evidence-manifest.json 等）不回改。
  3. 若日后需要重新取证，可依据同目录 `SHD-11-a-hdr-override-guard.inputs.json`
     与 `*.transcript.jsonl` 重放；或将该用例标注废弃并安排重测——二选一
     属后续 session 决策，本文件不代决。

## 3. 采集工具侧建议（非强制门禁）

1. **非必需不启 verbose**：`mpv -v` 只在诊断需要时使用；常规冒烟/验证用例
   用默认日志级别即可（现状：`tools/p4_collect.py` 启动 mpv 时仅传
   `--log-file=`，无 verbosity 控制——实测该文件 1851 行；P4 session 实测
   已累积约 83MB 日志）。
2. **单日志尺寸上限**：采集器宜设单日志上限（如 100MB，超限即截断并写
   明截断事实），超限时优先检查是否为空转/verbose 组合，而不是继续写。
3. **会话生命周期**：回放结束后的空转应及时结束会话，避免无信息量日志
   持续膨胀。

## 4. 撤销本默认决策的条件与步骤

若未来决定将证据入库：先确认体积可接受（含压缩方案），再修订本文件与
`.gitignore`——移除 `/docs/验证/开发/` 规则、按需为 `.log` 追加否定规则
（如 `!docs/验证/开发/**/*.log`），并以小样实测 `git check-ignore -v` 与
`git add -n` 验证规则在当时的 git 版本下行为符合预期后再全量提交。
